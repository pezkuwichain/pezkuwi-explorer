# i-Wallet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 5th explorer tab, `/i-wallet`, that lets an iPhone user hold a mainnet hot wallet in Safari. They can create or import it, send HEZ/PEZ/USDT and do citizenship work.

**Architecture:**
- Client-only React screens under `src/iwallet/`.
- They use their own mainnet config and connection cache, and never touch the Zagros `NETWORK` the other tabs use.
- Keys are a polkadot-js encrypted JSON keystore in IndexedDB. Optional Face ID unwraps the password through WebAuthn PRF.
- Transfers sign on Asset Hub. Citizenship signs on People. Teleport moves HEZ Asset Hub → People.

**Tech Stack:**
- React 19, react-router 7, i18next, Vite, vitest + Testing Library.
- `@pezkuwi/api` 16.5.39, `@pezkuwi/keyring` 14.0.26 (new), `@pezkuwi/util(-crypto)` 14.0.26.

**Spec:** `docs/superpowers/specs/2026-10-16-i-wallet-design.md`

## Global Constraints

- **Pezkuwi packages only:** `@pezkuwi/*`, never `@polkadot/*`. Add exactly `@pezkuwi/keyring@14.0.26` (pinned, no caret), and nothing else.
- **Strings:** no user-facing string in a component. Every string is an i18n key under `iwallet.*`, in all six locale files (`kmr` default; `ckb`, `fa`, `ar` RTL).
- **Code comments** in English.
- **Network values** are copied verbatim from spec §3. Mainnet values live only in `src/config/iwallet-network.ts`.
- **CSP:** the `connect-src` in `deploy/nginx-explorer.conf` gains `wss://rpc.pezkuwichain.io wss://asset-hub-rpc.pezkuwichain.io wss://people-rpc.pezkuwichain.io` in the same commit as that config file.
- **Signed extensions:** every mainnet `ApiPromise.create` passes `signedExtensions: { AuthorizeCall: { extrinsic: {}, payload: {} }, StorageWeightReclaim: { extrinsic: {}, payload: {} } }`.
- **Large amounts:** the warning threshold is `1000 HEZ` = `1000n * 10n ** 12n` TYR, and it applies to HEZ sends only.
- **Deposit:** the citizenship deposit is read live from `api.consts.identityKyc.kycApplicationDeposit` (1 HEZ measured), never hard-coded.
- **Never logged, sent or copied by the app:** mnemonic, password, decoded secret key and personal form data. No `console.*` of them, no network call carrying them, no `navigator.clipboard` write of words.
- **Touch and contrast:** touch targets at least 44 px. Colours come only from `src/ui/theme.css` tokens; new tokens go in both the light and dark blocks.
- **Repo gates:** `npm run typecheck && npm run lint && npm test && npm run build` green after every task; `npm run check-deps` green.

## Review Focus

1. **Safari clears site data / private mode.**
   - IndexedDB is unavailable or empty → the tab shows "no wallet" plus the import path, never a crash.
   - A storage write that fails tells the user the wallet was NOT saved.
2. **Wrong password / Face ID cancelled.**
   - The user gets a clear error, stays locked, and can retry.
   - A cancelled Face ID prompt falls back to the password field.
3. **Amount edge cases.**
   - Covers "", "0", "1,5" (comma as decimal mark), more decimals than the token has, and an amount > free balance.
   - Max leaves the ED for HEZ (keepAlive).
   - The 1000 HEZ gate checks the parsed amount, not the typed text.
4. **Invalid or own recipient.**
   - Bad checksum or hex → error.
   - Sending to self → a warning (allowed).
   - A Zagros-format address works too: ss58 42 on both chains.
5. **Citizenship with an empty People balance.**
   - The teleport offer appears.
   - After the teleport lands, the apply button enables without a reload, by polling the balance.

### Task 2: Keystore

**Files:**
- Create: `src/iwallet/keystore.ts`, `src/iwallet/keystore.test.ts`, `src/iwallet/idb.ts` (a tiny promise wrapper over one IndexedDB store `iwallet`, key `keystore` / `faceid`)
- Modify: `package.json`, `package-lock.json` (add `@pezkuwi/keyring@14.0.26`)

**Interfaces:**
- Produces:
  - `newMnemonic(): string` — 12 words.
  - `isValidMnemonic(m: string): boolean` — 12 or 24 words; trims and collapses whitespace, lowercases.
  - `quizIndices(): [2, 6, 10]` — zero-based; fixed per spec: words 3, 7, 11.
  - `quizOptions(words: string[], index: number, rand?: () => number): string[]` — 3 options, including the right word, no duplicates.
  - `createKeystore(mnemonic: string, password: string): Promise<{ address: string; json: KeyringPair$Json }>` — sr25519, ss58 42, `meta.name = 'i-Wallet'`.
  - `unlock(json, password): Promise<KeyringPair>` — throws `WrongPasswordError`.
  - `saveWords(mnemonic, password): Promise<boolean>`, `loadWords(password): Promise<string>` — the words encrypted with `jsonEncrypt`/`jsonDecrypt` (`@pezkuwi/util-crypto`), stored in idb key `words`; deleted with the keystore.
  - `saveKeystore(json): Promise<boolean>`, `loadKeystore(): Promise<KeyringPair$Json | null>`, `deleteKeystore(): Promise<void>`.
  - `requestPersistence(): Promise<boolean>`.
  - `passwordStrength(p: string): 0|1|2|3|4`. The minimum to accept is length ≥ 8, i.e. strength ≥ 2.

Steps:

  - The tests must cover:

    - a wrong password throws `WrongPasswordError`;
    - a 13-word or misspelled mnemonic is invalid;
    - `quizOptions` always contains the right word and has 3 unique entries;
    - `saveKeystore` returns false when the store throws.
  - The unlocked pair's `toJson` must never be called without a password.
- [ ] Implement it. Call `cryptoWaitReady()` once, lazily.

### Task 3: Face ID (WebAuthn PRF)

**Files:**
- Create: `src/iwallet/faceid.ts`, `src/iwallet/faceid.test.ts`

**Interfaces:**
- Produces:
  - `faceIdSupported(): Promise<boolean>` — true only when `PublicKeyCredential` exists, `isUserVerifyingPlatformAuthenticatorAvailable()` is true, and `getClientCapabilities?.()` reports `extension:prf` (when the call is absent: optimistic true, confirmed at enrolment).
  - `enrolFaceId(password: string): Promise<boolean>` — creates a platform credential (`rp.id = location.hostname`, `userVerification: 'required'`, `residentKey: 'preferred'`, `extensions: { prf: { eval: { first: SALT } } }`). If the result does not carry `prf.results.first`, it returns false and stores nothing. Otherwise it stores `{ credentialId, iv, ciphertext }` (AES-GCM of the password) in idb key `faceid`.
  - `unlockWithFaceId(): Promise<string | null>` — returns the password, or null on cancel or failure.
  - `forgetFaceId()`.
  - `SALT` is a fixed 32-byte constant: `sha256('pezkuwi-iwallet-faceid-v1')`.

Steps:
- [ ] Write the tests, mocking `navigator.credentials` and `crypto.subtle`:
  - unsupported → false;
  - enrol without PRF output → false and nothing stored;
  - enrol + unlock round-trip returns the password;
  - a cancelled `get()` → null.
- [ ] Implement it, then nail-check the PRF-missing branch.
- [ ] Gates; commit `Add optional Face ID unlock for i-Wallet`.

### Task 7: Send

**Files:**
- Create:
  - `src/iwallet/amount.ts` + test: `parseAmount(text, decimals): bigint | null`, accepting `.` or `,` and returning null on more decimals than allowed or a non-number
  - `src/iwallet/tx.ts` + test: `buildTransfer(api, token, to, amount)`, `estimateFee`, `maxSendable(free, fee, ed, token)`, `submit(tx, pair, onStatus)`, `friendlyError(api, dispatchError, t)`
  - `src/iwallet/errors.ts`: ported from pwap `shared/lib/error-handler.ts` lines 64-90 and 303-377, `identityKyc.*` / `tiki.*` / `balances.*` / `assets.*` entries, keyed by `pallet.Error` to i18n keys
  - `src/iwallet/screens/Send.tsx` + test
- Modify: locale files

**Rules:**
- HEZ: `api.tx.balances.transferKeepAlive(to, amount)` on Asset Hub.
- PEZ / USDT: `api.tx.assets.transfer(1|1000, to, amount)` on Asset Hub.
- The fee is `(await tx.paymentInfo(address)).partialFee`.
- Max:
  - for HEZ, `free − fee − ED(3333333)`;
  - for assets, the asset balance.
- **Gate:**
  - token HEZ and amount > `1000n * 10n**12n` → orange alert + `iwallet.send.largeAck` checkbox;
  - confirm is disabled until it is ticked.
- Confirm asks for the password or Face ID, then `unlock` → sign.
- Status:
  - `isInBlock` → "in block";
  - `isFinalized` → success screen with a link to `/payment?code=<extrinsic hash>`;
  - `dispatchError` → `friendlyError`, with a non-module fallback `iwallet.error.generic`.
- Recipient: `normaliseAddress`. Own address → `iwallet.send.self` warning.

Steps:
- [ ] Tests:
  - `parseAmount('1,5', 12) === 1500000000000n`;
  - `parseAmount('0.1234567', 6) === null`;
  - the gate at exactly 1000 HEZ → no warning, and at 1000.000000000001 → warning;
  - the gate never shows for USDT 5000;
  - max for HEZ keeps the ED;
  - `friendlyError` maps `identityKyc.ApplicationAlreadyExists`.
  - Builders, against a stubbed api: assert the method and args for each token.
- [ ] Nail check: remove the gate condition; the test goes red; restore.
- [ ] Implement; gates; commit `Add sending from i-Wallet`.
